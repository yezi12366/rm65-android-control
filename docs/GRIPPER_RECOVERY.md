# 1.15.1 常接夹爪检测与首次启用修复

原程序连接后只发送一次 24V 供电指令；必须先读到夹爪在线且使能才能发任何夹爪指令。官方夹爪状态接口说明指出，部分固件从首次控制夹爪起才开启状态更新，因此可能一直收到零值状态却无法首次控制。旧页面又把等待回复和控制器报告离线合并成“未检测”。这与夹爪是否物理插着并不等价。

现在先查询 `get_tool_voltage`，已是 24V 时不重复配置供电；读到非 24V 时，仅在没有运动或录制的情况下设置一次 24V，再读回确认。没有断电重启步骤。供电查询每轮最多连续尝试三次，然后每五秒继续查询；供电写入不因接收超时反复重发。手动“重新检测”重新开始读回及一次供电配置机会，不开合夹爪。检测、供电读回和故障恢复都复用当前 TCP 会话。

空闲夹爪每秒查询一次，尚未就绪时每 500ms 重查，夹爪执行期间每 150ms 查询；同一时刻只保留一个状态请求，超过原有 500ms 请求期限才允许重试。普通夹爪控制和动作回放必须有三秒内有效、在线、已使能、无故障且带有效工作模式的夹爪状态；末端供电读回要求十二秒内有效。超时及解析错误不会被当成夹爪已拔出，也不会通过缓存在线标志继续授权控制。下一帧有效状态自动恢复。

对于常接但冷启动未更新状态的夹爪，显示“启用并张开夹爪”。此按钮只有用户主动点击才发送一次 `set_gripper_release`，不能用作闭合动作的初始化通道。首次控制的五秒窗口内允许等待尚未使能/在线的初始反馈，但故障码立即失败；接收确认后仍需实际张开到位并连续两帧稳定才完成。超时不重发、不记录，沿用失败后关闭连接的会话隔离规则。动作回放、录制、手动点动、步进及坐标切换期间禁用初始化。初始化张开不写入动作库。

界面分别显示未连接、确认供电、等待回复、控制器报告离线、未使能、数据过期、回复异常和夹爪故障。故障位解码为堵转/过温/过流/驱动器/内部通信；没有软件自动清故障或切换末端 Modbus。新增“复制夹爪诊断”，包含状态字段、反馈年龄、供电读回、控制器软件信息及最近通信异常。
