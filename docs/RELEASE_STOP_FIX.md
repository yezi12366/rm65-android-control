# 1.14.1 按住控制松手停止修复

用户反馈“按住移动”松手后仍持续运动。本版在前端回归测试中复现了一个直接相关的时序缺陷：按下后、原生开始反馈之前到达的旧静止状态，会清空网页中的按压按钮与指针记录。之后松手事件因指针不匹配而被忽略，停止指令没有发出；失联停止关闭时也不会依靠其超时退出。

## 修改

- 原生状态回传不再结束网页的本地按压手势。只有松手、取消、失焦、断开或匹配的原生释放通知才清理手势。
- 网页本地按钮记录丢失但原生仍报告点动时，停止入口仍会请求停止。
- Android Activity 在 `dispatchTouchEvent` 中独立跟踪真实触摸。控制手指抬起、触摸取消或窗口失焦时，直接请求停止，覆盖 DOM 松手事件丢失的情况。
- 手动连续点动与按住回零开始前必须存在有效的原生按压；快速点击已经松开后才送达的开始请求会被拒绝。
- 原生释放通知包含本次手势编号，前端只清理匹配的按压，避免上一次迟到的释放通知取消下一次手势。
- 连续示教停止时请求 `set_stop_teach` 并补发 `set_arm_slow_stop`，复用现有发送优先级及排队命令清理逻辑。

新增 `ManualTouchGuard` 的状态只在 Android 主线程处理。第二根手指释放不能冒充控制手指，原控制手指释放后也不会把运动所有权转移给另一根手指。失联停止配置仍保留用户原值；原生松手保护不依赖此开关。

1/5/10 mm 是有限步进，松手后继续到达指定距离的交互保持原样；本次用户确认的问题发生在“按住移动”。

## 接口

手动控制入口新增本次手势编号，必须由同版网页调用：

```javascript
RobotBridge.startJog(mode, axis, direction, speed, holdId)
RobotBridge.startReturnToZero(speed, holdId)
```

`holdId` 是页面递增的正整数；原生推送 `manual_hold_released`，`data.hold_id` 标识已经结束的手势。此编号不用于机械臂 JSON 协议。自动动作回放和毫米步进沿用各自的确认流程。

## 验证范围

修复前新增的三个前端时序测试均失败；修复后通过。完整验证为 72 个 Kotlin/JUnit 测试、25 个 Node 测试、JavaScript 语法及界面状态逻辑检查，Gradle APK 构建与签名验证通过。

版本 1.14.1，versionCode 23，沿用正式包名和签名。已在 RM100 覆盖安装并启动；3 个已保存动作、IP 与原有设置值均保留校验一致，截图确认页面版本 v1.14.1。更新前保留旧 APK 和最新设置，安装记录位于工程上级目录 `device-backup-20261016/release-stop-1.14.1/`。

上述验证不包含实体机械臂的运动和实际停止距离。停止请求经 TCP 传输，控制器仍有减速过程；链路中断时软件不能保证停止请求到达。首次现场复验应在工作区清空、实体急停可用时，以 1% 速度短按并松开“按住移动”，确认停止行为，再继续其他操作。
