# RM65 动作记忆与动作库设计

## 目标

在现有 Android WebView 直连遥控台中增加动作记忆、中文动作库和一键执行。保留现有点动、夹爪、软件限位、失联停止和实时状态显示。

## 已确认的产品规则

- 动作库显示名称保存在 Android 端，通过稳定的动作 ID 与控制器内部短名称对应，中文名称不受控制器文件名长度限制。
- 遥控录制与拖动录制是互斥模式。
- 遥控录制不逐帧复制网络状态，而是在每次点动结束后保存最终实际六轴位置，避免网络抖动成为轨迹时钟。
- 拖动录制使用控制器原生 `start_drag_teach`/`stop_drag_teach` 记录；Android 不按网络回传逐点采样。
- 录制时自然产生的停顿默认不保存。等待必须通过“插入等待”显式添加。
- 动作可包含机械臂运动、夹爪张开、夹爪夹取、夹爪目标位置和显式等待。
- 执行前低速移动到动作起点；所有已知路点必须通过当前软件限位检查。
- 执行期间持续检查关节状态、故障、状态新鲜度和软件限位，异常时停止。

## 存储边界

### 控制器

- 拖动录制的连续轨迹使用控制器轨迹文件保存。
- 遥控录制的关键路点同时以内部名称保存为控制器全局路点（控制器支持时）。
- 控制器轨迹短名称采用 `A<时间戳后缀>S<段号>`，避免中文和长度限制。

### Android

- `SharedPreferences` 保存动作清单：动作 ID、中文名称、类型、默认速度、节点顺序、安全摘要、控制器轨迹名和控制器路点名。
- 该清单负责把多个控制器对象、夹爪节点和等待节点组织成“一键动作链”。
- Android 不复制拖动轨迹点；仅保存拖动段起点、终点和关节包络用于安全检查。

说明：公开 JSON 协议没有提供在控制器内保存任意中文元数据清单的接口，因此中文别名和动作链编排保存在 App；实际拖动轨迹和遥控关键路点保存在控制器。换遥控器时需要导入/恢复 App 的动作映射，未映射的控制器轨迹可重新绑定。

## 动作模型

`ActionRecord`：

- `id`：稳定字符串 ID。
- `displayName`：Android 端中文名称。
- `recordingType`：`REMOTE` 或 `DRAG`。
- `defaultSpeed`：1～30%。
- `createdAt`、`updatedAt`。
- `nodes`：按顺序保存动作节点。

节点类型：

- `WaypointNode`：六轴角度、控制器全局路点内部名、速度、是否连续通过。
- `DragTrajectoryNode`：控制器轨迹短名称、点数、起点、终点、六轴最小/最大包络。
- `GripperNode`：张开、力控夹取或目标位置。
- `WaitNode`：100～60000 ms 的显式等待。

## 录制状态机

### 遥控录制

1. 新建草稿并保存当前位置为起点。
2. 继续使用现有按住点动控制。
3. 松开按钮后先停止运动，再请求一帧新的机械臂状态；收到新帧后保存最终位置。
4. 与上一个路点六轴最大差值小于 0.05° 时去重。
5. 夹爪按钮在正常发送控制命令的同时追加对应节点。
6. 用户显式插入等待节点。
7. 结束时校验至少存在一个有效运动节点，保存控制器全局路点并写入本地动作清单。

### 拖动录制

1. 新建草稿，记录拖动段起点和初始安全包络。
2. 下发 `start_drag_teach`，参数 `trajectory_record=1`。
3. 用户在机械臂上拖动。
4. 下发 `stop_drag_teach`，再以内部短名称下发 `save_trajectory_file`。
5. 将控制器轨迹文件引用追加为拖动轨迹节点。
6. 用户可添加夹爪、等待并录制下一拖动段。
7. 保存草稿为正式动作。

如果轨迹通过机械臂绿色按钮独立录制，动作库中的“读取控制器轨迹”会调用 `get_trajectory_file_list`，用户选择轨迹后绑定中文名称。由于列表不含完整轨迹点，这类导入项标记为“未离线校验”；首次运行前需要用户在轨迹起点保存起点位置。

## 执行状态机

状态为 `IDLE`、`ALIGNING`、`RUNNING`、`PAUSED`、`STOPPING` 和 `FAILED`。

1. 校验连接、六轴使能、错误码、状态新鲜度和动作节点。
2. 校验所有已知关节角度均位于当前软件安全区。
3. 使用不高于 10% 的速度 `movej` 到动作起点。
4. 顺序执行节点：
   - 路点：`movej`，等待到位上报。
   - 拖动段：`set_run_trajectory_file`，等待 `trajectory_file_state`。
   - 夹爪：发送夹爪命令并等待命令确认。
   - 等待：Android 计时器，仅记录显式等待。
5. 暂停/继续使用机械臂暂停与继续接口；等待节点暂停时保存剩余时间。
6. 停止时终止拖动轨迹并发送机械臂缓停。

## 界面

- 顶栏增加“动作库”。
- 动作库覆盖层包括动作列表、新建遥控录制、新建拖动录制、读取控制器轨迹和刷新按钮。
- 动作卡片显示中文名称、来源、节点数、默认速度和控制器引用。
- 每项提供执行、重命名、删除。
- 录制条显示模式、节点数量、添加等待、结束保存和取消。
- 执行条显示动作名称、当前节点、暂停/继续和停止。
- 一键执行前显示确认框，并明确将先低速移动到起点。

## 安全与失败处理

- 录制和执行时禁止启动另一种录制或手动点动冲突操作。
- 拖动示教期间禁用普通点动和回零；急停与停止始终可用。
- 轨迹保存、查询或运行返回 `false` 时不把动作标记为成功。
- 断线、状态超时、掉使能、非零错误码或进入任一软件提前停止区时停止执行。
- 删除动作前二次确认。遥控录制产生的专用全局路点会尝试按名称删除；拖动轨迹文件保留在控制器中，由示教器管理。官方 JSON 删除接口要求轨迹 ID，而轨迹列表未保证返回 ID，因此 App 不用名称猜测 ID，避免误删。

## 验证范围

- 单元测试动作 JSON 往返、路点去重、限位校验和协议 JSON。
- Node 执行网页脚本语法与动作列表纯函数测试。
- Android 编译需要 JDK 17 与 Android SDK；当前机器缺少这两项，因此源码交付必须明确要求在 Android Studio 编译和真机验证。
- 实机验证从 1% 速度、空工作区和实体急停可用开始。
