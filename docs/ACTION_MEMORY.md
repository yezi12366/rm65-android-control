# 动作记忆与动作库使用说明

## 1. 两种录制方式

### 遥控录制

1. 连接机械臂，等待底部显示“关节状态正常”。
2. 打开“动作库”，输入中文名称和速度，点击“遥控录制”。
3. 用原来的关节或笛卡尔按钮控制机械臂。每次松开按钮，App 会等待一帧新的实际关节状态并保存最终路点。
4. 需要夹爪动作时直接点击张开、夹取或移动到位置；指令接收并且实际状态确认完成后才加入动作链。夹爪执行中不能重复发送、移动或结束保存；相邻且参数相同的夹爪节点只保留一个，中间有路点或等待时保留新的操作。
5. 需要停顿时选择时长并点击“插入等待”。普通操作间隔不会自动保存为等待。
6. 点击“结束并保存”。

这种模式保存的是关键路点链，不复制按住期间的每一帧，因此回放是各路点之间的 `movej`，不是完全复刻手部速度变化。

### 拖动录制

1. 连接后打开“动作库”，确认轨迹列表显示“读取成功”。真正的空列表允许开始新录制；查询失败或超时不能被当作空列表。列表下方会显示控制器返回的型号和软件信息。
2. 输入名称和速度，点击“拖动录制”，等待“控制器已确认开始拖动录制”，再按设备允许的方式手动拖动。
3. 若只录制一段，直接点击“结束并保存”。App 会先结束控制器录制，再保存轨迹文件，确认列表中出现同名且点数大于零的文件后自动保存动作。若要添加后续节点，先点击“结束当前拖动段”，等待确认保存完成。
4. 此时可操作夹爪、插入等待；若还有连续轨迹，点击“录制下一拖动段”。
5. 所有段完成后点击“结束并保存”。

拖动段的连续轨迹点由机械臂控制器记录和保存，网络状态回传只用于显示和形成采样安全包络，不作为轨迹时钟，因此不会因 Android 回传间隔改变轨迹形状。采样包络不能证明两个回传帧之间绝对没有越界，最终仍以控制器硬限位、安全回路和实体急停为准。

该路径依赖 `get_trajectory_file_list`、`save_trajectory_file` 和 `set_run_trajectory_file` 接口。它们见官方[第四代控制器轨迹文件协议](https://develop.realman-robotics.com/robot4th/json/trajectoryfile/)；官方[第三代拖动示教协议](https://develop.realman-robotics.com/robot/json/dragTech/)提供的 `save_trajectory` 是另一种轨迹点读取方式，不能直接替换文件保存命令。RM65 型号本身不能证明支持文件接口，需以当前控制器的实际回复为准。本版只在成功读取文件列表后开放控制器文件录制，不自动切换为其他未经实机验证的回放方式。

开始/停止命令等待最多 5 秒，文件保存等待最多 10 秒，文件确认等待最多 10 秒。文件列表暂未出现新文件时每 500 ms 尝试重新查询，同一时刻只保留一条未完成的列表查询。失败会显示具体原因，并保留草稿供查看；取消后可以刷新列表检查是否已有控制器文件，再按真实起点导入。失败的段不会被写入动作库，已确认保存的控制器文件不会被自动删除。

## 2. 导入机械臂已有拖动轨迹

如果已通过机械臂按钮独立录制轨迹：

1. 先把机械臂放到该轨迹真实起点。
2. 打开动作库，点击“刷新”。
3. 选择控制器轨迹，填写中文显示名称，点击“加入动作库”。

控制器的列表接口不返回完整轨迹点，所以 App 会把导入时的当前位置当作自动回起点目标，且无法预先验证整条轨迹的所有关节角。第一次运行必须用 1% 速度、清空工作区并准备实体急停。

## 3. 一键执行

1. 在动作卡片中设置本次速度并点击“执行”。
2. 阅读确认框，确认工作区清空后继续。
3. App 先用不高于 10% 的速度 `movej` 到动作起点，再依次执行路点、拖动轨迹、夹爪和显式等待。
4. 执行条可暂停、继续或停止。页面“立即停止”和实体急停始终可用。

动作卡片的速度用于自动回起点和遥控录制的 `movej` 路点。官方 `set_run_trajectory_file` 指令没有速度参数，因此控制器拖动轨迹段按其保存的节奏复现，不能由这个数值改速。

执行过程中仍会检查状态更新时间、六轴使能、错误码、控制器实际限位、软件限位和逐轴提前停止角度；异常会缓停并结束本次回放。

1.13.2 用实际到位和规划状态确认 `movej` 完成，用控制器轨迹文件完成事件确认拖动段完成；夹爪不再固定等待 800 ms，而是等待实际张开到位、闭合到位或力控停止。夹爪停止不代表已检测到物体牢固夹持。

暂停/继续机械臂运动需要控制器回复确认，确认等待期间禁止继续发送下一节点。暂停夹爪节点只暂停后续节点，当前夹爪仍可能完成。异常、控制器拖动段或夹爪节点停止时关闭本次连接；排除问题后重新连接，再重新执行动作。详情及超时设置见 [回放鲁棒性说明](PLAYBACK_ROBUSTNESS.md)。

## 4. 数据保存在哪里

- 中文名称、节点顺序、默认速度和控制器内部名称映射保存在当前 Android App 的 `SharedPreferences`。
- 拖动轨迹文件保存在机械臂控制器。
- 遥控路点以 Android 动作清单为准；App 也会尝试用内部短名称保存为控制器全局路点，但回放仍使用清单中的六轴角度。
- 卸载 App、清除应用数据或更换遥控器会丢失中文动作库映射，不会自动删除控制器拖动轨迹。

建议发布前由安卓同事增加动作库导出/导入或应用数据备份。当前公开 JSON 协议未提供把任意中文动作链元数据整体保存在控制器中的通用接口。

## 5. 删除与恢复

删除动作会删除 Android 端的动作库映射，并尝试删除该动作的专用全局路点。控制器拖动轨迹不会自动删除：官方 JSON 删除命令要求轨迹 ID，而轨迹列表未保证返回该 ID，App 不会用列表序号猜测，以免误删。请在示教器的轨迹文件管理中清理不再使用的拖动轨迹。

若动作执行中断，先排除故障、重新使能并确认六轴状态正常，再重新选择动作执行。App 会重新从低速回到动作起点开始，不会从中断节点盲目续跑。

页面会保留最近一次动作中断原因，可点击“复制中断原因”导出诊断。连接正常但停止时也需要查看实际状态更新时间、控制器故障和完成回复，不能仅据连接图标判断原因。

录制中断后，当前进程保留草稿。重新连接并确认状态后点击“继续录制”，遥控录制会补入当前实际路点；未确认的夹爪或拖动段不会保存。应用进程退出会丢失未保存草稿，不提供跨进程恢复。

## 6. 实机验收顺序

1. 速度设为 1%，只录制两个距离很近的路点，无夹爪、无等待。
2. 保存并执行，确认先回起点、再按顺序到位、停止有效。
3. 测试一个很短的控制器拖动段。
4. 再加入夹爪和 1 秒显式等待。
5. 最后测试多段拖动组合。

软件限位和 App 停止不能替代控制柜安全回路与实体急停。
