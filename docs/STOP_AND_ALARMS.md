# 1.15.4 停止确认与报警

本版针对 J5 松手后持续运动、软件立即停止无效的报告修改。设备读取证实安装版为 1.15.3，兼容失联停止被关闭；重启后的数据不能证明事故发生时停止指令的收发情况，因此不能声称唯一根因已经复现。

## 停止行为

- 所有关节点动、位置/姿态点动、联动、复位、步进取消与回放停止均进入 `ManualStopGate`，不再只在联动/复位松手时确认。
- 普通松手优先发送 `set_stop_teach` 与 `set_arm_slow_stop`；“立即停止”无论内部 `jogActive` 是否为真，均发送 `set_stop_teach` 与 `set_arm_stop`。后者是维持动力的受控快速停止，不是硬件急停。
- 必须收到两种停止指令各自字段的布尔确认，再收到确认后发起的 `type:none` 规划查询，以及 300ms 内至少三帧、全部六轴相对固定参考不超过 0.03° 的静止数据。位置数据须在 250ms 内，规划数据须在 1 秒内。
- 无回执 1 秒或未确认静止 2 秒后，标为“尚未确认停住”，升级受控快速停止，保持连接、锁住新运动并持续重试停止。停止回执拒绝、缺失或状态超时不会触发主动断联。收到迟到的有效确认后可在同一会话解锁，其他控制器故障仍阻止运动。
- 真实 TCP 断开、发送异常/阻塞等仍如实报告连接失效；程序不能在物理网络中断时保证软件停止到达机械臂。切到后台时若仍在等待停稳，保留通道继续重试；应用被销毁时仍会关闭自身资源。
- 录制的停止后路点推迟到确认停稳后采样，不记录滑行中的位置。

## 按住信号

所有按住操作每 150ms 发送带手势 ID 的心跳。原生独立线程每 50ms 检查，心跳间隔达到 500ms 或一次按住达到 5 秒时请求停止；不受旧版 `jog_watchdog_enabled` 设置影响。过期或旧手势的心跳不能恢复运动。触摸释放仍直接触发停止，500ms 是丢失释放/心跳的补充检查时限，不是物理停止时间保证。

到 5 秒须松手并重新按住；这也适用于联动和复位。设置页隐藏旧版可关闭的兼容选项，显示固定保护说明。

## 报警

顶部“报警状态”打开系统和关节报警详情，包含来源、中文名称、原始十进制/十六进制代码与处理提示。系统状态和全部状态中的系统错误合并显示，保留未知代码，不把缺失或过期状态当作零错误。断联时保留上次读数并明确标记为历史读数。

清除系统使用 `clear_system_err`，单个关节使用 `set_joint_clear_err`，不自动遍历清除。仅在没有手动运动、回放、录制或夹爪动作时允许请求，并先通过新状态和规划查询确认静止。收到指定字段的正回执后，再读取新系统/关节状态确认清除结果。清除不自动上使能、不恢复运动、不修改限位或碰撞保护；夹爪自身故障不承诺由系统清错修复。

官方第三代接口：

- [状态查询、系统清错](https://develop.realman-robotics.com/robot/json/armState/)
- [关节清错](https://develop.realman-robotics.com/robot/json/jointParameter/)
- [错误代码](https://develop.realman-robotics.com/robot/json/errorList/)
- [示教停止、受控快速停止](https://develop.realman-robotics.com/robot/json/motionConfig/)

## 验证边界

单元测试、WebView 界面逻辑测试和本机模拟 TCP 控制器覆盖停止回执拒绝/缺失、超时保留连接、迟到确认恢复、主线程延迟后的心跳失效、手势隔离、J5 在旧设置关闭时仍有心跳、界面认为静止时立即停止仍调用原生、报警过期及清除后复查。未执行真实机械臂运动或清错测试。

## 与旧版共存安装

构建时加 `-PsideBySide=true`，应用 ID 为 `com.realman.rm65webview.trial1154`，名称为“RM65 1.15.4 试用版”；正常构建仍保留原应用 ID。共存安装包为 `RM65_v1.15.4_side_by_side_debug.apk`，快捷方式名称也随应用名称区分。两应用使用不同的数据沙箱。安装脚本把旧版设置复制到新沙箱，并检查旧版 APK 和偏好文件没有变化；如果旧版仍运行，不启动试用版以免切换应用打断旧连接。运行时只使用一个应用连接机械臂。
